| **`studio:flow-doctor`** | Automation | Does a test run first, keeps the safety limits (no CAPTCHA bypass, no passwords in files), and explains the flow in plain words |

## How to call it

Type `/studio` and pick **`/studio:studio`** from the menu. Plugin skills always carry the plugin name in front. Then paste your full prompt **in the same message**, however long:

```
/studio:studio
P0 the hero subtext is still hard to read in dark mode...
the experience section should feel like a story, not stacked cards, here's what I mean: ...
also the cat enters from the left after leaving from the right...
(any length, voice-dictated is fine)
```

- **Long prompts are the intended use.** The first thing it does is turn your prompt into a numbered checklist with priorities. If anything is unclear it asks numbered questions before touching anything.
- **The same command works in every chat.** It reads the folder and your message to tell code from Figma from automation, so your code, Figma and automation prompts can each be completely different. Paste Figma links straight in.
- **To skip the detection step,** call the doctor directly: `/studio:code-doctor`, `/studio:figma-doctor` or `/studio:flow-doctor`, followed by your prompt.
- **On a tight budget,** add a line like "budget: conserve". It sizes each item and cuts to what fits, and the rest goes to the tracker.
- **Screenshots and reference GIFs** can go in the same message.

## A mod in one paragraph

`on(event, matcher?, hook)` adds a hook, and every hook is `($, e, next)`: `$` is the engine interface, each call spelled noun then method; `e` is the event's input, a plain frozen value; `next(e)` runs the plugins beneath and then the engine's own behaviour, resolving to the event's result. A hook that returns without `next` answers for itself; `next({ ...e, x })` rewrites what the rest sees. The module runs in an environment of its own, with no DOM and no Node: `$` reaches everything outside it. JSX compiles against the global `h`, and the elements come from the drawing surface's own table, `const { Box, Text, Button } = $.ui.resolve(e)`, where `e.surface` is `terminal`, `desktop`, `vscode` or `mobile`.

## How it works today

**When you call it:** `/studio:studio` or `/studio:flow-doctor`. Studio mode keeps later messages running through it, and the board panel shows progress.

| Step | What happens | What it uses |
|---|---|---|
| **Hard limits** (checked every run) | No getting past CAPTCHAs, no passwords in files, private answers never printed, unknown questions become "Needs you", daily caps, messages to people drafted only, terms risk written down before building | Skill text, `private.local.md` |
| **1. Intake** | Works out which project this is, reads the README tracker (requirements, answers, status), turns your note into a checklist ordered by priority | `detect.sh` |
| **2. Reproduce** | Finds the failing run (script log, Apps Script log, or a "Needs you" row) and repeats it as a dry run | `npm run instahyre:dry` / `:inspect` |
| **3. Diagnose** | One line per item: where it breaks, why, and the fix. Explains the flow as nodes and edges | Skill text |
| **4. Fix** | Smallest change that fixes it, safe to rerun, plain-word Sheet values with IST times (the rule from your feedback) | `truth.md` for cover notes |
| **5. Verify** | Dry run with log lines as proof, then one real application after your OK, then shows the Sheet row | `verify.md` |
| **6. Report** | Updates the README status and gives you about 5 plain lines | Board panel |
| **Always on** | Blocks force-push, flags em dashes, logs your corrections to FEEDBACK.md | Hooks, `feedback.sh` |

**The automation project itself:**
- `config.json`: job titles grouped into tracks, excluded words, cities, caps, notes.
- `filters.mjs`: decides fit or no fit, with a reason.
- `sheet.mjs`: writes rows, and holds them in a local queue if your Mac is offline.
- `login.mjs`: opens the bot's own Chrome for you to log in once.
- `apply.mjs`: the Instahyre bot.
- `timer.sh`: runs it every hour, 8am to 11pm.
- `Tracker.gs`: the Sheet and the web link your Mac posts rows to.

## The upgrades I'd make

**Before Wellfound (they change how a new site gets built):**

1. **A step for adding a new site.** Before any code:
   - check the site's terms and record your decision;
   - do a dry run that captures what the site loads and shows;
   - read the job data the page already receives, rather than scraping what's on screen;
   - show you 10 real jobs to say yes or no on, so the filters match your taste;
   - then 1 live application, then the timer.

   This step would have prevented "why didn't you apply here?".
2. **One shared plan for every site.** Each site gets the same five parts: log in, read the job list, read one job's details, apply, check if already applied. The filters, Sheet, caps, pacing, offline queue and re-check are shared. Instahyre gets reshaped this way first. That costs little now and saves a lot by the 4th site. It also stops you applying twice when Wellfound and Instahyre list the same job.
3. **A Runs tab in the Sheet.** One row per run: site, jobs seen, matched, applied, Needs you, skipped by reason, near misses, errors, next run.
4. **A health line at the top of the Sheet**, plus `npm run status`. It shows the last good run, the next run, today's count against the cap, and whether the login is still valid. It turns red if nothing has worked for 3 hours or the login expired. No Telegram.
5. **No more manual Apps Script deploys.** You sign in once with Google's Apps Script command-line tool (it's called clasp). After that, flow-doctor pushes Sheet changes and redeploys them itself.

**After that:**

6. **A safety check at the start of each run.** If the site's layout changed, that site stops and is marked "needs fix" instead of misapplying. A page capture is saved automatically, and only the last few runs are kept. Your debug folder already holds 40+ files.
7. **The Sheet treated like a design.** Columns, widths, formats and dropdowns defined once in code. Old rows get fixed when the format changes, such as the 3 rows still showing codes.
8. **A cap across all sites,** for example 15 a day total with your top companies first. 10 per site across 4 sites is 40 a day, which looks like spam and lowers quality.
9. **One standard flow page per project.** Update the same scroll-through page, keep it a simple node diagram, and test it at phone width.
