- **Build a lean "spine" (beats + evidence source) before refining full script prose.** Don't keep iterating word choices on a full script when the underlying complaint is structural.
  **Why:** On the Transform video, Anandhi's repeated note was the script "kept the intent, but it's still surface level... the features don't come out as well." That's not a wording problem — a fully-worded script can't fix a scene that hasn't decided what it's proving or how.
  **How to apply:** When a script gets "surface level" feedback twice, stop polishing VO and instead write a bones-only spine: one line per beat (problem → enter Tetriz → feature 1 → feature 2 → recap → CTA → close), and for each feature beat, name the *specific real product screen/artifact* that will carry the depth. See [[project-video-pipeline]].

- **Not everything needs to be spelled out in VO — visuals can carry feature depth.** Anandhi: "maybe the visuals will solve for that because not everything needs to be spelled out either."
  **Why:** Over-explaining a feature in VO reads as generic/surface-level even when accurate. A specific dashboard screenshot (real conflict, real number, real install button) proves the feature more convincingly than a sentence describing it.
  **How to apply:** For each feature scene, split what VO states (the outcome/claim) from what the visual proves (the specific evidence). Flag open questions about which screen is the right one — don't guess if unsure, ask Mohit/product.

- **The nicely-formatted teaser v4 doc was NOT AI-generated formatting — it was manual iteration over many feedback rounds**, per Anandhi directly: "the initial one, yes [AI got a first draft], but post that it went through a lot of discussions and feedback... we worked directly on the video." Divya did more of the hands-on generation on that one.
  **Why:** Corrects an assumption — there's no special tool/prompt that produces that polish in one shot; it accrued through rounds of manual editing.
  **How to apply:** Don't chase a one-shot "make it look like v4" tool investment as the priority. A scripted docx generator (like the one built for v5) is still useful for consistency, but the actual bottleneck Anandhi cares about right now is the story spine, not formatting polish.

- **This video does not need "SEO video" framing** (e.g. the "view" section structure used in SEO scripts) — Anandhi confirmed explicitly it's not needed here. Keep SEO-script and launch-script structures separate, consistent with [[feedback-working-style]].
