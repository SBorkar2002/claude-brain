**VERIFICATION GOTCHA — preview pane freezes animations (2026-08-04, DURABLE, cost hours):** the in-app Browser pane runs with `document.visibilityState === "hidden"`, so **CSS transitions AND framer-motion rAF animations DO NOT ADVANCE — they freeze at their START value.** DOM-probing an *animated* end-state there gives false "stuck/inverted" readings (e.g. an open accordion row measured collapsed, a closed row measured open, `grid-template-rows` computed stale). This is the SAME root as blank screenshots + `whileInView` never firing. Do NOT "fix" logic based on these probes. To verify logic that involves a transition: (a) check React-driven values only — `className`, `aria-expanded`, flex classes (these are always correct); or (b) temporarily set `style.transition='none'`, force reflow (`void el.offsetHeight`), then read `getComputedStyle` — the instant value equals the class's true target. Smoothness/animation feel simply CANNOT be verified in-pane; build it correctly and ask Sejal to confirm in her real browser.
